## 4. 第一步：打分别和三个 Key 计算匹配分数

`打` 的 Query 是：
```text
q_打 = [1,1,0]
```
三个 Token 的 Key 是：
```text
k_我   = [1,0,0]
k_喜欢 = [1,1,0]
k_打   = [0,1,1]
```
`q_打` 分别与三个 Key 点积：
```text
打 -> 我：   [1,1,0] · [1,0,0] = 1
打 -> 喜欢： [1,1,0] · [1,1,0] = 2
打 -> 打：   [1,1,0] · [0,1,1] = 1
```
所以 `打` 这一行的原始匹配分数是 `[1.0, 2.0, 1.0]`。
第二个分数最高，表示在这个教学例子里，`打` 最倾向读取 `喜欢`。

## 5. 第二步：把三个分数变成读取比例

先看转换总览，再逐个展开三个操作：

| 阶段 | 数值 | 作用 |
| --- | --- | --- |
| 原始分数 | `[1.0, 2.0, 1.0]` | 比较三个来源的匹配强弱 |
| 除以 `sqrt(3)` | `[0.577, 1.155, 0.577]` | 控制分数幅度 |
| Causal Mask | 数值不变 | `打` 是提示词最后一个位置，可以读取三个位置 |
| Softmax | `[0.264, 0.471, 0.264]` | 变成总和为 1 的读取比例 |

### 5.1 为什么除以 sqrt(3)

`3` 来自 Query 和 Key 的向量长度：`q_打=[1,1,0]` 一共有 3 个分量，
所以本例 `d_k=3`，缩放因子是：
```text
sqrt(d_k) = sqrt(3) = 1.732
```
把三个原始分数分别除以 1.732：
```text
1 / 1.732 = 0.577
2 / 1.732 = 1.155
1 / 1.732 = 0.577

[1,2,1] -> [0.577,1.155,0.577]
```
缩放没有改变大小顺序：`喜欢` 的分数仍然最高。它只控制分数幅度，
避免向量维度增大时，点积分数自然变大并让 Softmax 过度极端。

#### 控制变量实验 A：只改变分数差距

固定两个候选项，并固定第二项分数更高。唯一主动改变的变量是两项的分数差距：
```text
分数差距 1：[0,1] -> Softmax -> [26.9%,73.1%]
分数差距 2：[0,2] -> Softmax -> [11.9%,88.1%]
分数差距 4：[0,4] -> Softmax -> [ 1.8%,98.2%]
```
**观察结果：** 只要输入差距变大，Softmax 就会让输出比例变得更极端。

#### 控制变量实验 B：固定同一组分数，只改变是否缩放

现在固定 `d_k=16`、原始分数 `[0,4]` 和同一个 Softmax。
唯一主动改变的条件是：进入 Softmax 前是否除以 `sqrt(16)=4`。
```text
不缩放：
[0,4] -> Softmax -> [1.8%,98.2%]

缩放：
[0,4] / 4 = [0,1]
[0,1] -> Softmax -> [26.9%,73.1%]
```
**观察结果：** 同一组原始分数经过缩放后，大小顺序不变，但权重不再过度极端。

#### 两个实验如何连接

在真实模型的统计规律中，`d_k` 增大时，点积分数的典型幅度约按 `sqrt(d_k)` 增长。
实验 A 说明“分数差距变大”会让 Softmax 变尖；实验 B 说明缩放可以抵消这部分放大。
真实模型每次点积的具体分数不会固定等于 `[0,4]`，这里仅用于控制变量观察。

### 5.2 Causal Mask 检查哪些位置允许读取

Causal 的意思是：当前位置只能读取自己和左侧，不能读取右侧的未来 Token。
当前 Query 来自最后一个位置 `打`：
```text
位置：       [我, 喜欢, 打]
打能否读取： [是,   是, 是]
Mask 数值：  [0,    0,  0]
```
Mask 会加到缩放分数上。三个位置都允许读取，所以这一行数值不变：
```text
[0.577,1.155,0.577] + [0,0,0] = [0.577,1.155,0.577]
```
如果当前 Query 是中间的 `喜欢`，右侧的 `打` 属于未来位置，Mask 才会是：
```text
[我, 喜欢, 打] -> [0, 0, -inf]
```
`-inf` 经过 Softmax 后会得到 0 权重，表示完全禁止读取。

### 5.3 Softmax 把分数变成比例

Softmax 对 `[0.577,1.155,0.577]` 做三步。实际计算先减去最大值，
这样指数不会产生过大的数，而且最终比例不变：
```text
① 减去最大值 1.155：[-0.577, 0.000, -0.577]
② 每项取 exp：       [0.561, 1.000, 0.561]
③ 除以总和 2.123：[0.264, 0.471, 0.264]
```
现在三个数都非负，并且总和为 1，所以可以直接解释成读取比例。

这组结果只表达一句话：
> `打` 从 `我` 读取 26.4%，从 `喜欢` 读取 47.1%，从自己读取 26.4%。

## 6. 第三步：按比例读取三个 Value

为了让混合结果一眼可见，本例使用：
```text
v_我   = [1,0,0]
v_喜欢 = [0,1,0]
v_打   = [0,0,1]
```
按照上一步的权重加权求和：
```text
o_打 = 0.264 x v_我
     + 0.471 x v_喜欢
     + 0.264 x v_打

     = [0.264, 0.471, 0.264]
```
这个新向量已经混合了三个位置的信息，因此不再只表示孤立的 `打`。

## 8. 技术附录：逐 Token 写法和矩阵写法是什么关系

主线只计算了 `打` 这一行：
```text
q_打 @ K.T -> [1,2,1]
```
真实实现会把三个 Query 放进大写 `Q`，并行计算所有行：
```text
Q @ K.T =
[[1,1,0],   # 我读取各位置的分数
 [0,1,1],   # 喜欢读取各位置的分数
 [1,2,1]]   # 打读取各位置的分数
```
小写 `q_打` 是大写 `Q` 的第三行。矩阵写法只是同时完成每个 Token 的同类计算。

### 8.1 Causal Mask 对前两个位置做了什么

在推理的 Prefill 阶段，三个提示词 Token 会并行计算，但每个位置只能看自己和左侧：
- `我` 只能读取 `我`；
- `喜欢` 可以读取 `我、喜欢`；
- `打` 可以读取 `我、喜欢、打`。
本课跟踪的 `打` 已经位于最后，所以它这一行没有被 Mask 删除任何位置。

### 8.2 为什么要除以 sqrt(d_k)

点积会把 `d_k` 个乘积相加。维度越多，分数的典型幅度通常越大，
Softmax 也会因此变得过度极端。除以 `sqrt(d_k)` 用来抵消这种维度增益。
它不会改变哪个分数最大，只控制分数差距进入 Softmax 时不要无谓放大。
