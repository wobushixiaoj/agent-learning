## 3. 用一句人话理解 Q、K、V

当 `打` 读取上下文时，可以把三个对象理解成：

| 对象 | 本例中的问题 |
| --- | --- |
| `q_打`（Query） | `打` 当前想从上下文寻找什么？ |
| 每个 `k`（Key） | `我`、`喜欢`、`打` 各自适不适合被读取？ |
| 每个 `v`（Value） | 如果读取这个 Token，真正取回什么信息？ |

真实模型通过 `XW_Q`、`XW_K`、`XW_V` 得到这些向量。
下面使用人为挑选的 3 维数字，只为了完整看清一次计算。

## 4. 第一步：打分别和三个 Key 计算匹配分数

`打` 的 Query 是：
```text
q_打 = [1,1,0]
```
三个 Token 的 Key 是：
```text
k_我   = [1,0,0]
k_喜欢 = [1,1,0]
k_打   = [0,1,1]
```
`q_打` 分别与三个 Key 点积：
```text
打 -> 我：   [1,1,0] · [1,0,0] = 1
打 -> 喜欢： [1,1,0] · [1,1,0] = 2
打 -> 打：   [1,1,0] · [0,1,1] = 1
```
所以 `打` 这一行的原始匹配分数是 `[1.0, 2.0, 1.0]`。
第二个分数最高，表示在这个教学例子里，`打` 最倾向读取 `喜欢`。

## 5. 第二步：把三个分数变成读取比例

从原始分数到读取比例，依次经过三个操作：

| 阶段 | 数值 | 作用 |
| --- | --- | --- |
| 原始分数 | `[1.0, 2.0, 1.0]` | 比较三个来源的匹配强弱 |
| 除以 `sqrt(3)` | `[0.577, 1.155, 0.577]` | 控制分数幅度 |
| Causal Mask | 数值不变 | `打` 是提示词最后一个位置，可以读取三个位置 |
| Softmax | `[0.264, 0.471, 0.264]` | 变成总和为 1 的读取比例 |

这组结果只表达一句话：
> `打` 从 `我` 读取 26.4%，从 `喜欢` 读取 47.1%，从自己读取 26.4%。

## 6. 第三步：按比例读取三个 Value

为了让混合结果一眼可见，本例使用：
```text
v_我   = [1,0,0]
v_喜欢 = [0,1,0]
v_打   = [0,0,1]
```
按照上一步的权重加权求和：
```text
o_打 = 0.264 x v_我
     + 0.471 x v_喜欢
     + 0.264 x v_打

     = [0.264, 0.471, 0.264]
```
这个新向量已经混合了三个位置的信息，因此不再只表示孤立的 `打`。

## 8. 技术附录：逐 Token 写法和矩阵写法是什么关系

主线只计算了 `打` 这一行：
```text
q_打 @ K.T -> [1,2,1]
```
真实实现会把三个 Query 放进大写 `Q`，并行计算所有行：
```text
Q @ K.T =
[[1,1,0],   # 我读取各位置的分数
 [0,1,1],   # 喜欢读取各位置的分数
 [1,2,1]]   # 打读取各位置的分数
```
小写 `q_打` 是大写 `Q` 的第三行。矩阵写法只是同时完成每个 Token 的同类计算。

### 8.1 Causal Mask 对前两个位置做了什么

在推理的 Prefill 阶段，三个提示词 Token 会并行计算，但每个位置只能看自己和左侧：
- `我` 只能读取 `我`；
- `喜欢` 可以读取 `我、喜欢`；
- `打` 可以读取 `我、喜欢、打`。
本课跟踪的 `打` 已经位于最后，所以它这一行没有被 Mask 删除任何位置。

### 8.2 为什么要除以 sqrt(d_k)

点积会把 `d_k` 个乘积相加。维度越多，分数的典型幅度通常越大，
Softmax 也会因此变得过度极端。除以 `sqrt(d_k)` 用来抵消这种维度增益。
它不会改变哪个分数最大，只控制分数差距进入 Softmax 时不要无谓放大。

## 9. 本课结论

```text

-> 按比例混合三个 Value

```
