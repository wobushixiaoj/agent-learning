## 步骤 3：QK^T 计算 Token 两两之间的匹配分数

本步骤要回答：每个 Token 与每个 Token 的匹配程度是多少？

### 3.0 先别背规则：它只是批量计算匹配分数

先只问一个非常具体的问题：**`tools` 和 `Agent` 匹不匹配？**

它们各有 4 个特征数字。把同一位置的数字相乘：

| 特征位置 | 1 | 2 | 3 | 4 |
| --- | ---: | ---: | ---: | ---: |
| `tools` Query | 1 | 1 | 0 | 1 |
| `Agent` Key | 1 | 0 | 1 | 0 |
| 对应位置相乘 | 1×1=1 | 1×0=0 | 0×1=0 | 1×0=0 |

然后把最后一行加起来：

```text
1 + 0 + 0 + 0 = 1
```
这个 `1` 就是 `tools` 对 `Agent` 的一个原始匹配分数。

但 Attention 不只需要这一个分数：
- `tools` 还要分别和 `uses`、`tools` 比较；
- `Agent` 和 `uses` 也要分别和三个 Token 比较；
- 3 个读取者 × 3 个信息来源，总共要计算 **9 个分数**。

> `Q @ K.T` 只是把这 9 次同样的计算一次性完成。

所以在本节里，可以先把矩阵乘法理解为：**批量计算两两匹配分数**。
它不是 Attention 新增的一种判断逻辑，只是省去逐个计算的写法。

### 3.1 为什么要写 K.T？

Q 和 K 原本都是“一行代表一个 Token”：
Q 的形状是 (3, 4)：3 个 Token，每个 Query 有 4 个数。
K 的形状也是 (3, 4)。

计算时，需要让一个 Query 横着与一个 Key 竖着对齐。
K.T 就是把 K 的每个 Token 从一行转成一列，形状从 (3, 4) 变成 (4, 3)。

**转置后的 K.T**，形状：`(4, 3)`
```text
[[1. 0. 1.]
 [0. 1. 1.]
 [1. 1. 0.]
 [0. 0. 1.]]
```
这样才能进行矩阵乘法：

```text
Q (3, 4) @ K.T (4, 3) -> 原始分数 (3, 3)
```
这三个形状数字现在可以翻译成人话：
- 中间的 `4` 和 `4`：每次比较的 Query 和 Key 都有 4 个特征；
- 左侧的 `3`：有 3 个读取者；
- 右侧的 `3`：有 3 个候选信息来源；
- 最终 `3 × 3`：得到 9 个两两匹配分数。

### 3.2 一个格子的数字怎么计算？

每个格子都是一行 Query 与一行 Key 的点积：
```text
点积 = 对应位置相乘，再把乘积全部相加
```

完整手算 'tools' 这一行：
```text
tools 的 Query = [1, 1, 0, 1]
Agent 的 Key   = [1, 0, 1, 0]
uses 的 Key    = [0, 1, 1, 0]
tools 的 Key   = [1, 1, 0, 1]

tools 与 Agent：1x1 + 1x0 + 0x1 + 1x0 = 1
tools 与 uses： 1x0 + 1x1 + 0x1 + 1x0 = 1
tools 与 tools：1x1 + 1x1 + 0x0 + 1x1 = 3
```

**尚未缩放的 QK^T 原始分数**（行=读取者，列=信息来源）：

| 读取者 \ 来源 | Agent | uses | tools |
| --- | ---: | ---: | ---: |
| Agent | 2.000 | 1.000 | 1.000 |
| uses | 1.000 | 2.000 | 1.000 |
| tools | 1.000 | 1.000 | 3.000 |

### 3.3 为什么原始分数还要缩放？

每个向量有 4 维，所以 sqrt(4) = 2.0。
把每个原始分数都除以 2：

```text
tools -> Agent：1 / 2 = 0.5
tools -> uses： 1 / 2 = 0.5
tools -> tools：3 / 2 = 1.5
```
缩放用于避免向量维度较大时点积过大，让后面的 Softmax 过于极端。

**缩放后的 Attention 分数**（行=读取者，列=信息来源）：

| 读取者 \ 来源 | Agent | uses | tools |
| --- | ---: | ---: | ---: |
| Agent | 1.000 | 0.500 | 0.500 |
| uses | 0.500 | 1.000 | 0.500 |
| tools | 0.500 | 0.500 | 1.500 |

到这里得到的仍是匹配分数，还不是最终读取比例。

## 步骤 4：Causal Mask 禁止偷看未来，再用 Softmax 变成比例

GPT 按从左到右生成文本，因此当前位置只能读取自己和左边的 Token。
例如 'Agent' 后面的 'uses' 和 'tools' 对它来说都属于未来。

Softmax 把允许读取的分数转换为 0 到 1 之间的权重。
列顺序： ['Agent', 'uses', 'tools']

**Attention 权重**，形状：`(3, 3)`
```text
[[1.    0.    0.   ]
 [0.378 0.622 0.   ]
 [0.212 0.212 0.576]]
```
每一行权重之和： [1.0, 1.0, 1.0]

把每一行翻译成人话：
- 'Agent' 读取信息的比例：Agent 100.0%，uses 0.0%，tools 0.0%
- 'uses' 读取信息的比例：Agent 37.8%，uses 62.2%，tools 0.0%
- 'tools' 读取信息的比例：Agent 21.2%，uses 21.2%，tools 57.6%

## 步骤 5：按照 Attention 权重，对 V 向量加权求和

现在不是选择某一个 Token，而是按比例混合多个 Token 的 V。

**融合上下文后的向量**，形状：`(3, 4)`
```text
[[1.    0.    1.    0.   ]
 [0.378 0.622 1.    0.   ]
 [0.788 0.788 0.424 0.576]]
```

以 'tools' 为例，它的新向量来自：
- `0.212 x 'Agent'` 的 V 向量
- `0.212 x 'uses'` 的 V 向量
- `0.576 x 'tools'` 的 V 向量

因此，'tools' 的新向量不再只包含自己，也混入了前文信息。

## 本节总结

```text
输入向量 X -> Q、K、V -> QK^T 匹配分数 -> Causal Mask -> Softmax 权重 -> 对 V 加权求和 -> 上下文化向量
```
