# Day 2：Self-Attention 如何读取上下文

## 当前位于哪里

Day 1 已经让每个 Token 拥有自己的输入向量。本节只研究这些向量如何互相读取：

```text
输入向量 X
-> Q、K、V
-> Token 两两匹配分数
-> Causal Mask
-> Softmax 权重
-> 对 V 加权求和
-> 上下文化向量
```

## 先补一个前置：矩阵形状

Shape 的严格数学含义始终是 `(行数, 列数)`。本节矩阵严格来说是 3 行 4 列：

```text
X.shape = (行数, 列数) = (3, 4)
```

然后才能解释本教程赋予行列的语义：每一行放一个 Token 的向量，每一列放向量的
一个分量。因此在**本例的数据布局中**，也可以解释为：

```text
(Token 数量, 每个 Token 的向量维度) = (3, 4)
```

这两句话不冲突：前者是 Shape 的定义，后者是本例对行和列的语义映射。不能脱离
具体数据布局，把 Shape 的第一个数字永远解释为 Token 数量。

| 行 | Token | 四维向量 |
| ---: | --- | --- |
| 1 | `Agent` | `[1, 0, 1, 0]` |
| 2 | `uses` | `[0, 1, 1, 0]` |
| 3 | `tools` | `[1, 1, 0, 1]` |

所以 `(3, 4)` 是下面矩阵的尺寸说明，不是另一组计算结果。矩阵共有
`3 x 4 = 12` 个数字。

## 本节只解决什么

```text
一个 Token 如何决定从其他 Token 读取多少信息？
```

为了隔离这一个问题，教程暂时设置 `Q = K = V = X`。真实模型使用三组可训练
矩阵生成 Q、K、V，后续课程再展开。

## 步骤 3：匹配分数到底怎么计算

步骤 3 的完整链路是：

```text
矩阵乘法：左边一行与右边一列算出一个格子
-> 检查内侧维度是否相同
K 转置
-> Q 的每一行与 K 的每一行做点积
-> 得到 QK^T 原始分数
-> 除以 sqrt(向量维度)
-> 得到缩放后的 Attention 分数
```

### 3.0 先别背规则：它只是批量计算匹配分数

完整的 Q 仍然是 3 行 4 列，每个 Token 占一行：

| Q 中的行 | Query 向量 | 本次是否选中 |
| --- | --- | --- |
| `Agent` | `[1, 0, 1, 0]` |  |
| `uses` | `[0, 1, 1, 0]` |  |
| `tools` | `[1, 1, 0, 1]` | 是，抽出第 3 行 |

截图里的 `tools Query` 只有一行，是因为当前只演示一个问题：`tools` 和 `Agent`
匹不匹配？它不是说整个 Q 只有一行。类似地，`Agent Key` 是从完整 K 中抽出的第 1 行。

在当前单头示例里，一个 Token 对应当前 head 中的一个 Query 向量，因此抽出来就是
一行 4 个分量。两者各有 4 个特征数字，把同一位置的数字相乘，再相加：

| 特征位置 | 1 | 2 | 3 | 4 |
| --- | ---: | ---: | ---: | ---: |
| `tools` Query | 1 | 1 | 0 | 1 |
| `Agent` Key | 1 | 0 | 1 | 0 |
| 对应位置相乘 | 1 | 0 | 0 | 0 |

```text
1 + 0 + 0 + 0 = 1
```

这个 `1` 就是 `tools` 对 `Agent` 的一个原始匹配分数。接下来还要计算 `tools`
对另外两个 Token 的分数，并且让 `Agent`、`uses` 也分别做同样的事。3 个读取者
乘 3 个信息来源，一共需要计算 9 次。

`Q @ K.T` 只是把这 9 次完全相同的“对应位置相乘再求和”一次性写完。矩阵乘法
在这里不是新的业务动作，而是批量计算工具。

### 3.1 严格形状、标准理论与本例语义

标准的二维数学记号可以写成：

```text
Q: (n_q, d_k)       n_q 个 Query，每个 Query 是 d_k 维
K: (n_k, d_k)       n_k 个 Key，每个 Key 是 d_k 维
K.T: (d_k, n_k)
Q @ K.T: (n_q, n_k)
```

Self-Attention 中 Query 和 Key 来自同一序列，通常 `n_q = n_k = n`。本例取
`n = 3`、`d_k = 4`，所以：

```text
Q     的形状：(3, 4)
K.T   的形状：(4, 3)
矩阵乘法：    (3, 4) @ (4, 3) -> (3, 3)
```

输出的每一行代表一个读取者，每一列代表一个候选信息来源。因此 3 个 Token
两两匹配，会产生 `3 x 3 = 9` 个分数。

真实多头 Attention 还会加入 batch 和 head 维度，常见内部布局是
`(batch, heads, sequence_length, head_dim)`。不同框架的维度顺序可能不同，因此没有
唯一“官方存储顺序”；稳定不变的是最后两维参与的计算关系和
`softmax(QK^T / sqrt(d_k))V`。

参考：[Attention Is All You Need](https://arxiv.org/abs/1706.03762)、
[PyTorch MultiheadAttention](https://docs.pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html)。

### 3.2 一个格子如何计算

以 `tools` 读取 `Agent` 为例：

```text
tools Query = [1, 1, 0, 1]
Agent Key   = [1, 0, 1, 0]

点积
= 1x1 + 1x0 + 0x1 + 1x0
= 1
```

向量维度是 4，所以缩放因子是 `sqrt(4) = 2`：

```text
缩放后的分数 = 1 / 2 = 0.5
```

同理，`tools` 对三个 Token 的原始分数是 `[1, 1, 3]`，缩放后得到
`[0.5, 0.5, 1.5]`。

### 3.3 为什么除以 `sqrt(4)`

向量维度越大，点积结果通常越大，容易让后面的 Softmax 权重过度集中。因此用
`sqrt(向量维度)` 缩放；本例就是除以 `sqrt(4) = 2`。
