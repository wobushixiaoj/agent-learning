# Day 2：Self-Attention 如何读取上下文

## 当前位于哪里

Day 1 已经让每个 Token 拥有自己的输入向量。本节只研究这些向量如何互相读取：

```text
输入向量 X
-> Q、K、V
-> Token 两两匹配分数
-> Causal Mask
-> Softmax 权重
-> 对 V 加权求和
-> 上下文化向量
```

## 先补一个前置：矩阵形状

本节有 3 个 Token，每个 Token 使用 4 维向量：

```text
X.shape = (Token 数量, 每个 Token 的向量维度) = (3, 4)
```

| 行 | Token | 四维向量 |
| ---: | --- | --- |
| 1 | `Agent` | `[1, 0, 1, 0]` |
| 2 | `uses` | `[0, 1, 1, 0]` |
| 3 | `tools` | `[1, 1, 0, 1]` |

所以 `(3, 4)` 是下面矩阵的尺寸说明，不是另一组计算结果。矩阵共有
`3 x 4 = 12` 个数字。

## 本节只解决什么

```text
一个 Token 如何决定从其他 Token 读取多少信息？
```

## 步骤 3：匹配分数到底怎么计算

步骤 3 的完整链路是：

```text
矩阵乘法：左边一行与右边一列算出一个格子
-> 检查内侧维度是否相同
K 转置
-> Q 的每一行与 K 的每一行做点积
-> 得到 QK^T 原始分数
-> 除以 sqrt(向量维度)
-> 得到缩放后的 Attention 分数
```

### 3.0 先别背规则：它只是批量计算匹配分数

Attention 此时想解决的朴素问题是：`tools` 和 `Agent` 匹不匹配？两者各有 4 个
特征数字，就把同一位置的数字相乘，再相加：

| 特征位置 | 1 | 2 | 3 | 4 |
| --- | ---: | ---: | ---: | ---: |
| `tools` Query | 1 | 1 | 0 | 1 |
| `Agent` Key | 1 | 0 | 1 | 0 |
| 对应位置相乘 | 1 | 0 | 0 | 0 |

```text
1 + 0 + 0 + 0 = 1
```

这个 `1` 就是 `tools` 对 `Agent` 的一个原始匹配分数。接下来还要计算 `tools`
对另外两个 Token 的分数，并且让 `Agent`、`uses` 也分别做同样的事。3 个读取者
乘 3 个信息来源，一共需要计算 9 次。

`Q @ K.T` 只是把这 9 次完全相同的“对应位置相乘再求和”一次性写完。矩阵乘法
在这里不是新的业务动作，而是批量计算工具。

### 3.1 为什么输出是 `(3, 3)`

```text
Q     的形状：(3, 4)
K.T   的形状：(4, 3)
矩阵乘法：    (3, 4) @ (4, 3) -> (3, 3)
```

输出的每一行代表一个读取者，每一列代表一个候选信息来源。因此 3 个 Token
两两匹配，会产生 `3 x 3 = 9` 个分数。

### 3.2 一个格子如何计算

以 `tools` 读取 `Agent` 为例：

```text
tools Query = [1, 1, 0, 1]
Agent Key   = [1, 0, 1, 0]

点积
= 1x1 + 1x0 + 0x1 + 1x0
= 1
```

向量维度是 4，所以缩放因子是 `sqrt(4) = 2`：

```text
缩放后的分数 = 1 / 2 = 0.5
```

同理，`tools` 对三个 Token 的原始分数是 `[1, 1, 3]`，缩放后得到
`[0.5, 0.5, 1.5]`。

### 3.3 为什么除以 `sqrt(4)`

向量维度越大，点积结果通常越大，容易让后面的 Softmax 权重过度集中。因此用
`sqrt(向量维度)` 缩放；本例就是除以 `sqrt(4) = 2`。
