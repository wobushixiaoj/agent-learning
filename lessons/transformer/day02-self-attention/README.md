## 步骤 3：匹配分数到底怎么计算

步骤 3 的完整链路是：

```text
矩阵乘法：左边一行与右边一列算出一个格子
-> 检查内侧维度是否相同
K 转置
-> Q 的每一行与 K 的每一行做点积
-> 得到 QK^T 原始分数
-> 除以 sqrt(向量维度)
-> 得到缩放后的 Attention 分数
```

### 3.0 矩阵乘法只需先掌握三条

对于 `A @ B`：

1. 结果中的一个格子，来自 `A` 的一行和 `B` 的一列；
2. 一行与一列的计算方式是对应位置相乘，再全部相加；
3. `A` 的列数必须等于 `B` 的行数，结果形状是 `A 的行数 x B 的列数`。

所以：

```text
(3, 4) @ (4, 3) -> (3, 3)
 左边 4 = 右边 4：每次参与点积的两个向量都有 4 个数
 输出 3 x 3：左边有 3 行，右边有 3 列，共计算 9 个格子
```

矩阵乘法不是把两个矩阵相同位置的数字直接相乘。可以先把它理解为：批量执行
“行向量与列向量的点积”。

### 3.1 为什么输出是 `(3, 3)`

```text
Q     的形状：(3, 4)
K.T   的形状：(4, 3)
矩阵乘法：    (3, 4) @ (4, 3) -> (3, 3)
```

输出的每一行代表一个读取者，每一列代表一个候选信息来源。因此 3 个 Token
两两匹配，会产生 `3 x 3 = 9` 个分数。

### 3.2 一个格子如何计算

以 `tools` 读取 `Agent` 为例：

```text
tools Query = [1, 1, 0, 1]
Agent Key   = [1, 0, 1, 0]

点积
= 1x1 + 1x0 + 0x1 + 1x0
= 1
```

向量维度是 4，所以缩放因子是 `sqrt(4) = 2`：

```text
缩放后的分数 = 1 / 2 = 0.5
```

同理，`tools` 对三个 Token 的原始分数是 `[1, 1, 3]`，缩放后得到
`[0.5, 0.5, 1.5]`。

### 3.3 为什么除以 `sqrt(4)`

向量维度越大，点积结果通常越大，容易让后面的 Softmax 权重过度集中。因此用
`sqrt(向量维度)` 缩放；本例就是除以 `sqrt(4) = 2`。
