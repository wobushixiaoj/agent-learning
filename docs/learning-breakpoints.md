本文件记录学习者真实提出的问题，以及问题如何反向修改教材。它不是错题流水账，
而是知识链缺口与课程改进的索引。

| ID | 原问题或原理解 | 断点类型 | 缺失的逻辑关系 | 教材处理 |

| ATT-001 | `(3, 4)` 和三行四列的数字是什么关系？ | prerequisite | Shape 是矩阵尺寸；行对应 Token，列对应向量维度 | Day 2 步骤 1 增加行列、总元素数和 Token 映射 |
| ATT-002 | 步骤 3 太模糊，看不明白 `QK^T` 的计算过程 | prerequisite | 教材从矩阵直接跳到分数，缺少转置、点积、缩放和形状变化 | Day 2 步骤 3 展开完整手算，并加入 `(3,4) @ (4,3) -> (3,3)` |
| ATT-003 | 矩阵乘法最好也简单快速介绍用到的知识 | prerequisite | 教材给出了形状规则和点积结果，但没有先解释矩阵乘法如何逐格产生结果 | Day 2 增加 `3.0 矩阵乘法速通`：左矩阵的一行乘右矩阵的一列，并解释内侧维度与输出形状 |
| ATT-004 | “矩阵乘法速通”仍然没有很朴素、直观地讲清楚 | context-induced | 教材仍从抽象规则和形状出发，没有先说明 Attention 实际想批量完成什么任务 | 改为先手算 `tools` 与 `Agent` 的一次特征对比，再说明矩阵乘法只是批量完成 3×3 次同类比较，最后推导转置与形状规则 |
| ATT-005 | `(3, 4)` 不是 3 行 4 列吗？“3 个 Token、每个 Query 4 个数”与标准理论哪个准确？ | precision | 教材混写了 Shape 的严格数学定义和当前数据布局的业务语义，没有说明理论记号与工程张量布局的差异 | 统一先写 `(行数, 列数)`，再解释本例“行=Token、列=向量分量”；补充 `Q:(n_q,d_k)`、`K:(n_k,d_k)` 标准记号及 batch/head 维度说明 |
| ATT-006 | `tools` Query 为什么只有一行？ | context-induced | 单次点积示例直接展示了一个 Query 向量，却没有说明它是从完整 Q 矩阵中抽取的第 3 行 | 在计算表前同时展示完整 Q/K 和被选中的 `tools` 行、`Agent` 行；明确完整 Q 仍是 3×4，一行只代表一个 Token 在当前 head 的 Query 向量 |

## 状态说明

- `concept`：概念方向或机制混淆，需要保留修正链路与迁移自测；
- `precision`：主线正确但措辞会导致更高阶误解；
- `context-induced`：教材缺少前置上下文，不归因成学习者能力问题；
- `prerequisite`：课程假设了尚未建立的数学或编程直觉，需要补前置解释。
